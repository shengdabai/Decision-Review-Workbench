# 决策复查工作台

## 定位

这是一个纯本机决策日志。它把“事前预测”和“事后复查”分开保存，并用 Brier 分数检查已复查二元预测的概率误差。Brier 分数是预测概率与实际结果差值平方的平均值；越低表示这组记录的概率误差越小。

## 目标用户

首位使用者是 Tony。适用于希望保留原始判断、按日期复查、避免事后重写理由的个人。

## 如何打开

双击 `index.html`。工具不需要安装、登录或联网。固定日历时区为 `Asia/Shanghai`。测试日期时可打开 `index.html?today=2026-10-29`；页面会持续显示固定基准日和上海日历口径。

## 核心任务

1. 填写标题、可检验问题、0–100% 事前概率、复查日期、理由和可选证据。
2. 复查日期到达后选择“发生”或“未发生”，追加复查结论、偏差分类和下一次检验。
3. 用全部、到期、未到期和已复查筛选队列。
4. 导出 JSON 备份或 Markdown 记录。JSON 导入先校验和预览数量，确认后才整份替换。
5. 如原研究页保存过 `decision-lab-20261026-v1`，页面会提供显式迁移。旧内容只作为原文存档，不进入校准统计。

## 证据来源

产品方向来自原研究页《用 AI 改进判断：决策日志与错题本》。原页建议保存事前理由、概率、复查日期和证据，但只能保存一份 `before / after` 自由文本。本工具补齐多条记录、复查队列、来源隔离和导入导出。

没有真实使用记录，也没有付款证据。合成示例持续逐条标记，和用户录入共存时仍显示“包含合成示例”，并从真实 Brier 分数中排除。

## 数据与恢复

- 浏览器键：`decisionReviewWorkbench.v2`。
- 原研究页只读迁移键：`decision-lab-20261026-v1`。
- 修订未复查预测会新增版本。已有结果后不能改事前预测。
- 结果仍未知时不保存结果，继续留在复查队列。
- 本地存储失败时，已提交的当前内存记录继续显示。若表单有草稿，普通导出仍会禁用；先保存或取消草稿，再使用“导出已提交的当前内存记录 JSON”。这样不会把未保存草稿静默漏出备份。
- 使用者填写的复查日期是自报信息。它不能早于最后预测版本对应的上海日历日，也不能晚于基准日。工具自动保存不可编辑的复查写入时间，并检查决策创建、预测版本和复查写入的先后顺序。同一上海日历日内，这些检查不证明现实事件先后；任何时间都不证明使用者身份或现实事件实际发生时间。
- 删除单条、载入示例、导入备份和清空全部数据都使用页内确认；确认前数据不变。

## 设计系统

`styles.css` 顶部 `:root` 是唯一 token 来源，按 primitive → semantic 组织颜色、间距、字体、边框、圆角、阴影、尺寸、层级和动效。媒体查询断点集中为 980px 和 620px。组件样式只消费 token；媒体查询阈值是 CSS 限制下的集中登记字面量。

## 已知限制

- 只支持二元结果；连续值、多分类结果和未决结果不计算分数。
- Brier 分数需要足够多、口径一致的真实记录才有解释价值。本工具不设“好/坏”阈值。
- 不验证输入证据、身份、自报日期或结果真实性。本机写入时间只支持本地审计顺序。
- `file://` 的站点数据归属由浏览器决定。清理浏览器数据会删除记录，因此需要定期导出 JSON。
- 没有提醒推送、云同步或多人协作。
